# A3 perf: rigged figures on the board

Measured with `node docs/status/a3/capture.mjs perf gpu` (real GPU through ANGLE/D3D11, RTX 5080) and `... perf sw` (SwiftShader, what `npm run e2e` uses), on `dist/`, 1280x720. The scene: 4 troopers and the 3 syndicate units the squad can see, after two rounds. Every sample forces a redraw each animation frame for 90 frames. **Headless numbers are relative, not what a phone will do**; the GPU run is vsync-capped at 16.7 ms, so it shows headroom, not cost.

| Case | Draw calls | Triangles | Frame ms (GPU run) | Frame ms (SwiftShader) | `gl.render` CPU ms | Rig CPU ms / frame | Mixers updated / frame |
|---|---|---|---|---|---|---|---|
| Static figures only (no anim manifest) | 115 | 290k | 16.7 | 106 | 0.9 (sw 2.1) | 0 | 0 |
| Real manifest: Enforcer rigged, the rest static | 116 | 330k | 16.7 | 117 | 0.7 (sw 1.7) | 0.02 (sw 0.12) | 0.2 (sw 1) |
| Synthetic: every kind rigged with the Enforcer mesh and shotgun, Normal tier | 122 | 571k | 16.7 | 204 | 0.7 (sw 2.7) | 0.07 (sw 0.54) | 1.1 (sw 6.9) |
| Same, Low tier (`lite`) | 122 | 571k | 16.7 | 207 | 0.9 (sw 2.5) | 0.04 (sw 0.06) | 0 (7 frozen) |

How to read it
- **Draw calls.** A rigged figure is one skinned mesh plus one draw per attachment; clones from `SkeletonUtils.clone` share geometry and material, so 7 rigged figures cost +7 draw calls (the shotgun) over the static ones, and the shader program count goes 10 to 11 (the skinned variant). Materials are shared per kind, never cloned per unit.
- **Where the time goes.** The rigs' own CPU (mixer update plus clip logic) is 0.07 ms per frame for seven animated figures on the GPU machine. The slowdown on SwiftShader is the **triangle count** (the A0 Enforcer mesh is about 40k faces, the static GLBs are lighter): 571k triangles with seven rigged figures, so A1 should keep the per-figure budget at or below the A0 mesh (a decimated 20-25k body would halve the cost). This is a software-GL effect; on the GPU the frame stays at vsync.
- **Standing figures.** Idle breathing needs about 10 frames a second. Standing figures advance their mixer every 0.1 s and ask the on-demand canvas for a redraw on a timer (`scheduleIdleFrame`), not every frame. Moving or acting figures update every frame.
- **Quality tier.** `lite` (the existing Low switch in Settings) freezes standing figures completely (7 frozen, 0 updates above), and any tier skips the mixer of figures outside the camera frustum (`skippedOffscreen` in `window.__px.animStats()`); a figure returning to view catches up (its accumulated time is capped at 0.5 s).
- **Not measured:** a real phone; a roster of 17 different rigged meshes (all variants above use the same Enforcer mesh, so texture and geometry memory are optimistic: 19 textures and 94 geometries here); the first-use shader compile of the skinned program (the start screen already draws the rigged Enforcer behind the card, so it compiles before New Operation is pressed, rule 26 and the scene-start recipe).

## Locomotion and foot skating (finding for the coordinator)
`walk.speed` in the manifest is the ground speed that keeps feet planted: 0.538 units per second for a 1.8-unit figure. The board draws every figure 1.0 tile tall (scale 0.556), so a planted walk is 0.3 tiles per second, while the game moves units at 5.9 tiles per second for rigged figures (170 ms per tile; 7.4 for a dash) and 8.7 for static ones. The player runs `walk` at `ground speed / (speed x scale)` but clamps the rate to 3.5x natural (about 2.6 strides per second), against about 20x needed at 5.9 tiles per second, so **a planted foot covers only about 18% of the ground the figure travels** (the legs read as a fast jog, the body glides); stride phase does follow distance (it speeds up and slows with the path), it is only capped. Options if the owner wants less skating: slower on-board movement (a rigged move of 6 tiles would take about 5 s at planted speed, too slow), a `run` clip with a longer stride at the dash speed (A1 can bake `run` with a speed near 1.8 units/s, which this player will use automatically), or a larger figure scale. I left the figure at the existing 1.0-tile height.
